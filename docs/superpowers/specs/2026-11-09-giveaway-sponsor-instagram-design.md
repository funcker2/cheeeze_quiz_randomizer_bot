# Instagram спонсора в розыгрыше

## Задача

Призы в розыгрышах CheeseQuiz часто дают спонсоры (кафе, магазины, партнёры).
Спонсору нужна видимая ссылка на его Instagram в посте канала. Сейчас админ
вставляет ссылку в текст приза руками: непоследовательно, легко забыть, а
share-ссылки тащат за собой мусор вроде `?igsh=…`.

Нужно необязательное поле «Instagram спонсора» у розыгрыша, которое бот сам
показывает в посте анонса и в посте итогов.

## Решения пользователя

| Вопрос | Решение |
|---|---|
| Как показывать спонсора в анонсе | Строкой в конце текста (не кнопкой) |
| Показывать ли спонсора в итогах | Да, строкой «Спонсор приза: 📸 Instagram @handle» |
| Значок перед ссылкой | 📸 + слово «Instagram» в тексте ссылки, чтобы было ясно, куда она ведёт (логотипа Instagram в стандартных эмодзи нет; custom emoji требует Fragment-username у бота) |
| Сколько спонсоров | Один на розыгрыш |
| Когда спрашивать | Отдельный шаг при создании, с пропуском; плюс редактирование в карточке |
| Где хранить spec | `docs/superpowers/` (как архив) |

## Контекст

- Пост розыгрыша = `prize_text` + `prize_entities` (+ `photo_id`), уходит в канал
  через `entities` / `caption_entities`, не HTML (`_publish_giveaway`, `bot.py:1599`).
- Пост итогов — ответ на анонс, `parse_mode="HTML"` (`_send_result_to_channel`, `bot.py:126`).
- После публикации текст поста больше не редактируется: обновление счётчика и все
  пути завершения меняют только `reply_markup` (`_kb_participate`, `_kb_finished`).
- Оригиналы в библиотеке (`game_id IS NULL`) копируются в игру через `copy_giveaway()`;
  публикуются копии.
- `Giveaway(*row)` распаковывается позиционно из `_GIVEAWAY_COLS` — новое поле
  добавляется **последним**, после `archived_at`.

Номера строк — по локальному `main`; `origin/main` впереди на 3 коммита (архив),
реализация идёт от `origin/main`.

## Модель данных

Новая колонка `sponsor_instagram TEXT` в `giveaways`. `NULL` — спонсора нет.
Хранится **handle** в нижнем регистре (`sunny_cafe.bg`), не URL. Ссылка
собирается при показе: `https://www.instagram.com/<handle>/`.

Почему handle: одна каноническая форма, удобно показывать как `@handle`, не
храним трекинг-параметры, формат URL меняется в одном месте.

Миграция в `init_db()` по образцу остальных:

```python
if "sponsor_instagram" not in cols:
    conn.execute("ALTER TABLE giveaways ADD COLUMN sponsor_instagram TEXT")
```

Бэкфилла нет. Старые розыгрыши остаются с `NULL` и выглядят как сейчас.

## Разбор ввода (`instagram.py`)

`parse_instagram(raw: str) -> str | None` — handle или `None`.

| Ввод | Результат |
|---|---|
| `@sunny_cafe.bg` | `sunny_cafe.bg` |
| `sunny_cafe.bg` | `sunny_cafe.bg` |
| `instagram.com/sunny_cafe.bg` | `sunny_cafe.bg` |
| `https://www.instagram.com/Sunny_Cafe.BG/?igsh=abc123` | `sunny_cafe.bg` |
| `http://m.instagram.com/sunny_cafe.bg` | `sunny_cafe.bg` |
| `https://www.instagram.com/p/C1abc/` | `None` (пост, не аккаунт) |

Правила:

- Хост: `instagram.com`, `www.instagram.com`, `m.instagram.com`.
- Берётся только первый сегмент пути.
- После lowercase: `^[a-z0-9._]{1,30}$`, не начинается и не заканчивается `.`, без `..`.
- Зарезервированные сегменты отклоняются: `p`, `reel`, `reels`, `stories`,
  `explore`, `tv`, `accounts`, `direct`.

Ошибка ввода — бот остаётся в том же состоянии:
«Это не похоже на Instagram-аккаунт. Пришли @handle или ссылку вида
instagram.com/handle. «Без спонсора» — пропустить, /cancel — отмена.»
Для ссылки на пост/reel — отдельный текст «Это ссылка на пост, а не на аккаунт…».

## Пост анонса: строка в конце текста

```
Разыгрываем сертификат на 50 лв в Sunny Cafe!

Спонсор: 📸 Instagram @sunny_cafe.bg   ← text_link на «Instagram @sunny_cafe.bg»
[ Участвую! 🎲 (12) ]
```

- Строка **рендерится, а не хранится**. Новый хелпер
  `_render_post(g) -> (text, entities)` возвращает
  `prize_text + "\n\nСпонсор: 📸 Instagram @handle"` и исходные entities плюс одну
  `text_link` на `Instagram @handle`. `prize_text` / `prize_entities` в БД не меняются,
  поэтому смена или удаление спонсора не портит текст админа.
- Offsets entities в Telegram — в UTF-16. Добавление в конец не сдвигает
  существующие entities; offset новой = UTF-16-длина
  `prize_text + "\n\nСпонсор: 📸 "` (📸 = 2 единицы).
  Хелпер `_utf16_len(s) = len(s.encode("utf-16-le")) // 2`.
- `_render_post` используют `_publish_giveaway` (фото и текст) и
  `on_view_giveaway` — превью у админа совпадает с каналом.
- После завершения строка остаётся: текст поста не редактируется, меняется
  только кнопка («Завершён ✅ (N)»). Клавиатуры не трогаем.

### Лимит длины

Подпись к фото — максимум 1024 UTF-16 единиц, текст — 4096. Шаг спонсора и
правки «Заменить текст» / «Заменить фото» проверяют длину отрендеренного поста.
Если не влезает — не сохраняем и пишем, на сколько сократить:

«Со спонсором подпись станет 1041 символ, лимит Telegram для фото — 1024.
Сократи текст на 17 символов («Заменить текст») или пропусти спонсора.»

Проверка при сохранении, а не при публикации — иначе `sendPhoto` упадёт в момент
выкладки в канал.

### Превью ссылки (только текстовые посты)

Telegram показывает превью первой ссылки. Если в тексте админа уже есть ссылка
(`url` / `text_link`), поведение не меняется — первой остаётся его ссылка. Если
нет — ссылка спонсора дала бы карточку Instagram, поэтому публикуем с
`link_preview_options=LinkPreviewOptions(is_disabled=True)`. У фото-постов
превью нет.

## Пост итогов

```
🎉 Результаты розыгрыша:

🏆 Победители:
  1. Иван (@ivan)

Приз: Сертификат на 50 лв
Спонсор приза: 📸 Instagram @sunny_cafe.bg   ← <a href="https://www.instagram.com/sunny_cafe.bg/">
```

Строка добавляется только если спонсор есть. Handle экранируется
`html.escape`. Превью ссылки отключено.

## Админ: создание

Новое состояние `NewGiveaway.waiting_sponsor` после контента:

```
waiting_name → waiting_content ─(фото без подписи)→ waiting_text_for_photo
                     │                                       │
                     └──────────────► waiting_sponsor ◄──────┘
                                           │
                     handle разобран ──────┤→ _save_giveaway()
                     «Без спонсора» / «-» ─┘
                     ошибка / лимит        → сообщение, остаёмся
```

- Сейчас `on_content_photo` (с подписью), `on_content_text`, `on_text_for_photo`
  сразу зовут `_save_giveaway()`. Теперь они переводят в `waiting_sponsor` и
  спрашивают: «Чей это приз? Пришли Instagram спонсора: @handle или ссылку
  instagram.com/handle» + inline-кнопка «⏭ Без спонсора» (`spn_skip`).
- Текст `-` / `нет` тоже пропускает шаг.
- Сообщение «✅ Розыгрыш #N сохранён» показывает `📸 Спонсор: @handle`, если есть.

## Админ: редактирование

В карточке розыгрыша (`on_view_giveaway`):

- Заголовок показывает `📸 Спонсор: @handle`, если задан.
- Кнопка `📸 Спонсор: @handle` / `📸 Спонсор: —` (`edsp:{gid}`) →
  `EditGiveaway.waiting_sponsor`, тот же разбор и проверки.
- Кнопка `✖️ Убрать спонсора` (`edsp_clr:{gid}`), только если задан.
- `update_giveaway(..., sponsor_instagram=None, clear_sponsor=False)` с текущим
  guard'ом `status IN ('queued','finished')`: опубликованный розыгрыш не
  редактируется, как и текст/фото сейчас.
- Панель «✅ Опубликовано» и карточка завершённого розыгрыша показывают спонсора.

## Библиотека, копии, архив

- `copy_giveaway()` копирует `sponsor_instagram` (снимок на момент копирования).
- Правка оригинала не меняет существующие копии — как с текстом и фото.
- Архив (`archived_at`) не затронут; возврат из архива сохраняет спонсора.

## Существующие данные

- Все старые розыгрыши — `NULL`, показываются как раньше.
- Активные на момент деплоя: пост уже отправлен, текст не редактируется —
  ничего не меняется. In-memory таймеры и `_pending_winners` теряются при
  рестарте как и сейчас, поэтому деплой — когда активных розыгрышей нет.

## Риски

| Риск | Защита |
|---|---|
| Порядок колонок не совпал с dataclass | `sponsor_instagram` последним в обоих местах; тест читает строку после миграции |
| Неверный offset (UTF-16 vs `len`) ломает форматирование или ссылку | `_utf16_len` + тест с эмодзи, кириллицей и существующими entities |
| Подпись > 1024 после строки спонсора — `sendPhoto` падает | Проверка при сохранении и правке |
| Нежелательное превью Instagram в текстовом посте | Отключаем превью, если у админа своих ссылок нет |
| Админ прислал ссылку на пост/reel | Зарезервированные сегменты отклоняются с понятным текстом |
| Спонсор сменил handle | Админ правит поле; уже опубликованные посты остаются со старой ссылкой |

## Вне задачи

- Несколько спонсоров на розыгрыш.
- Другие соцсети (TikTok, Facebook, сайт).
- Статистика кликов.
- Правка спонсора у опубликованного (активного) розыгрыша и правка уже отправленных постов.
