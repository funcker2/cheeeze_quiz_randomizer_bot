# Архив розыгрышей в библиотеке

## Задача

Библиотека накапливает розыгрыши, которые больше не нужны в ротации, но удалять
их жалко. Нужен архив: убрать розыгрыш из библиотеки одной кнопкой, при
необходимости вернуть обратно, а до тех пор не видеть его в списках.

Архивный розыгрыш нельзя добавить в игру. Из архива доступны только два
действия: вернуть в библиотеку и удалить.

## Контекст

Библиотека — это розыгрыши без привязки к игре:

```sql
SELECT ... FROM giveaways
WHERE game_id IS NULL AND status IN ('queued','finished') AND country = ?
```

(`database.py:270`, `get_free_giveaways`)

При добавлении в игру розыгрыш **копируется** (`copy_giveaway`, `database.py:294`),
оригинал остаётся в библиотеке. Значит архивация оригинала не влияет на копии,
уже живущие в играх, — они полностью независимые строки.

`get_free_giveaways` — единственный источник данных для трёх экранов:

- библиотека (`_show_library`, `bot.py:613`)
- «Добавить из библиотеки» внутри игры (`glib:`, `bot.py:715`)
- счётчик «📚 В библиотеке: N» в главном меню (`bot.py:928`)

Поэтому фильтр архива достаточно добавить в одном месте — все три экрана
подхватят его автоматически.

## Модель данных

Новая колонка `archived_at TEXT` в таблице `giveaways`. `NULL` — розыгрыш в
библиотеке, ISO-таймстемп — в архиве.

Флаг ортогонален статусу. Библиотечные оригиналы бывают и `queued`, и
`finished`, и при возврате из архива статус должен сохраниться — отдельная
колонка это даёт бесплатно, а `status='archived'` затёрло бы его. Плюс
`update_giveaway` и `delete_giveaway` фильтруют по `status IN ('queued','finished')`
и остаются рабочими без правок.

Миграция — по существующему паттерну в `init_db()`:

```python
if "archived_at" not in cols:
    conn.execute("ALTER TABLE giveaways ADD COLUMN archived_at TEXT")
```

Существующие строки получают `NULL`, то есть остаются в библиотеке. Отката
данных не требуется.

## Изменения в `database.py`

| Функция | Изменение |
|---|---|
| `init_db` | миграция колонки `archived_at` |
| `get_free_giveaways` | добавить `AND archived_at IS NULL` в оба ветвления запроса (с country и без) |
| `get_archived_giveaways(country)` | новая: `game_id IS NULL AND archived_at IS NOT NULL`, `ORDER BY archived_at DESC` |
| `archive_giveaway(gid)` | новая: `SET archived_at=? WHERE id=? AND game_id IS NULL AND archived_at IS NULL`, вернуть `rowcount > 0` |
| `unarchive_giveaway(gid)` | новая: `SET archived_at=NULL WHERE id=? AND archived_at IS NOT NULL`, вернуть `rowcount > 0` |
| `_GIVEAWAY_COLS` | добавить `archived_at`; синхронно добавить поле `archived_at: str \| None` в dataclass `Giveaway` |

Условие `game_id IS NULL` в `archive_giveaway` — барьер на уровне БД: копию,
привязанную к игре, заархивировать нельзя.

Поле `archived_at` в dataclass добавляется последним, после `source_id`, чтобы
порядок совпадал с `_GIVEAWAY_COLS` — распаковка идёт позиционно (`Giveaway(*row)`).

## Изменения в `bot.py`

### Кнопка «Архив» в библиотеке

В `_show_library` перед кнопкой «◀️ Меню» добавляется
`🗄 Архив (N)` → `show_archive`, где N = `len(db.get_archived_giveaways(country))`.
Кнопка показывается только при N > 0.

Это касается обеих веток `_show_library` — и заполненной библиотеки, и пустой:
библиотека может быть пуста именно потому, что всё ушло в архив, и без кнопки
в этом состоянии архив станет недостижим.

### Экран архива

`_show_archive(chat_id, message_id, page, user_id)` — по образцу `_show_library`:

- пагинация через `_paginate` / `PAGE_SIZE`, callback `arcpage:{page}`
- строки списка: `{icon} #{id}: {label}` → `arcview:{gid}`, иконка и подпись
  через существующие `_giveaway_label` и проверку `photo_id`
- заголовок: `🗄 Архив розыгрышей (N):`
- нижняя кнопка: `◀️ Назад в библиотеку` → `show_library`
- пустой архив: текст `🗄 Архив пуст.` и та же кнопка назад

Страна берётся через `_get_country(user_id)`, как во всех остальных экранах.

### Карточка архивного розыгрыша

`arcview:{gid}` — отдельный хендлер, не переиспользует `view:`. Показывает
превью (фото с caption либо текст с entities — та же логика, что в
`on_view_giveaway`), затем сообщение `🗄 Розыгрыш #{id} — в архиве` с тремя
кнопками:

```
↩️ Вернуть в библиотеку   → unarch:{gid}
🗑 Удалить                → del:{gid}
◀️ Назад в архив          → show_archive
```

Кнопок публикации, добавления в игру и редактирования здесь нет. Если розыгрыш
не найден или уже не в архиве — `cb.answer("Розыгрыш не в архиве")` и возврат
на экран архива.

### Кнопка «Перенести в архив»

В `on_view_giveaway` (`bot.py:1223`), в ветке `else` (розыгрыш без `game_id`,
то есть библиотечный), в `edit_buttons` перед «🗑 Удалить» добавляется
`🗄 Перенести в архив` → `arch:{gid}`. Для розыгрышей внутри игры кнопка не
появляется.

### Хендлеры действий

- `arch:{gid}` — `db.archive_giveaway(gid)`; при успехе показать экран
  библиотеки и тост `#{gid} перенесён в архив`; при неуспехе тост
  `Не удалось перенести в архив`.
- `unarch:{gid}` — `db.unarchive_giveaway(gid)`; при успехе показать экран
  библиотеки и тост `#{gid} возвращён в библиотеку`; при неуспехе тост
  `Не удалось вернуть`.
- `arcpage:{page}` — пагинация архива.
- `show_archive` — открыть архив со страницы 0.

Удаление из архива переиспользует существующий `del:{gid}` (`bot.py:1423`).
Он удаляет строку и уводит на экран библиотеки — приемлемо: розыгрыша больше
нет, оставаться в архиве незачем.

### Защита от устаревших клавиатур

Сообщения в Telegram живут долго, и админ может нажать кнопку «Добавить в игру»
на экране, отрисованном до архивации. Поэтому `on_lib_to_game` (`lib2game:`) и
`on_library_pick` (`gpick:`) перед копированием проверяют, что у розыгрыша
`archived_at IS NULL`, и при нарушении отвечают тостом
`Розыгрыш в архиве — сначала верни его в библиотеку`.

Итого архивный розыгрыш не попадёт в игру тремя барьерами: его нет в списках,
его карточка не рендерит кнопки игр, и копирование проверяет флаг явно.

## Подтверждения

Ни архивация, ни возврат, ни удаление из архива не спрашивают подтверждения.
Архивация и возврат обратимы. Удаление следует существующему поведению `del:`
в библиотеке — оно тоже срабатывает сразу.

## Проверка

Ручной прогон в боте, по шагам:

1. Библиотека с несколькими розыгрышами → открыть один → есть кнопка
   «🗄 Перенести в архив».
2. Нажать → розыгрыш исчез из библиотеки, счётчик в главном меню уменьшился,
   появилась кнопка «🗄 Архив (1)».
3. Открыть игру → «📚 Добавить из библиотеки» → архивного в списке нет.
4. Архив → тап на розыгрыш → превью корректное (фото/текст/форматирование),
   кнопок игр и редактирования нет.
5. «↩️ Вернуть в библиотеку» → розыгрыш снова в библиотеке, статус и название
   те же, добавляется в игру как обычно.
6. Заархивировать `finished`-розыгрыш и вернуть — статус остался `finished`.
7. Заархивировать всё → библиотека пуста, но кнопка «🗄 Архив (N)» на месте.
8. Удалить из архива → строки нет ни в библиотеке, ни в архиве.
9. Перезапуск бота на существующей БД → миграция прошла, старые розыгрыши
   в библиотеке.
10. Архив у одной страны не виден админам другой страны.
